Sonae Zitoun · technical presentation notes

How it is built, and how to answer the jury

Every technology we used and why we chose it, how each part works under the hood, and short answers to the technical questions a jury is likely to ask.

Live: https://sonae-zitoun.vercel.app · web app, API and database on Vercel + Neon, contract on Ethereum Sepolia.

One-line pitch: Sonae plans, day by day, where an olive mill's margine (olive-mill wastewater) can safely go as water and potassium for olive groves, and sells the grignon (pomace) as fuel. A blockchain ledger proves that no grove got more than the law allows.

1. Architecture in one picture

Web app (React 19)Plan, 3D twin, process, grove check, lab reader, Ask Sonae, accounts, Yui ledger, replay. Also runs as an installable PWA and an Android app (Capacitor).
API (Fastify 5, Node)Accounts and sessions, packs, season-plan generation, lab-report reading, Ask Sonae, admin, AI budget guard. Runs as a Vercel serverless function; data in Neon Postgres.
Smart contract (Solidity)ZitounLedger on Ethereum Sepolia: grove caps, load dispatch and delivery, grignon escrow, clean-oil certificates.
Engine (shared TypeScript)planZitoun: the deterministic planner. The same code runs in the browser, on the API and in tests.
Claude Opus 5.5 (Anthropic API)Reads lab reports, answers farmers, and writes the season plan. Called only from the API, never from the browser.
Open-MeteoFree weather API: 8-day rain, temperature and evapotranspiration (ET0) for any point in Tunisia.

Browser → /api on the same Vercel domain (HTTPS + session token) → Claude / Neon Postgres · Browser → Sepolia directly (wallet signs, viem reads) · Browser and API → Open-Meteo

Key design idea: the numbers come from code, the words come from AI. Caps, doses, rain blocks and distances are computed by the deterministic engine and enforced by the contract. The AI only explains, reads documents and writes the plan around numbers that the code already computed. So the AI can never authorise an unsafe spread.

3. The core: the margine planner

Input: the mills (pond volume and fill level, margine produced each day, tankers), the groves (area, slope, soil, distance to the nearest well and to the wadi, margine already received this season) and the 8-day weather forecast.

Output: for each day, which tanker carries how many m³ from which mill to which grove, which days are blocked and why, each pond's level, the potassium (K₂O) delivered, money saved, and SMS texts for the farmer and the driver.

Rules the planner enforces (from Tunisian practice and the scientific literature on margine spreading)

RuleValueWhy
Season cap per grove50 m³/haAbove this, salts and phenols build up in the soil.
Daily dose10 m³/ha/dayThe soil must absorb it; no run-off.
Rain blockNo spreading at ≥ 8 mm rain, or the day before rainRain would wash margine into the wadi and the groundwater.
Wet soilBlocked if 2-day rain ≥ 12 mmSaturated soil can't absorb more.
SlopeNever above 8 %Run-off.
Distances≥ 100 m from a well, ≥ 50 m from the wadiProtect drinking water.
Value≈ 4 kg K₂O per m³; olive need ≈ 80 kg K₂O/haConverts margine into fertiliser saved, in TND.
Grignon≈ 2.5 kg grignon replaces 1 kg dieselFuel value for the well-pump engine.

Algorithm (greedy, deterministic)

  • For each day: check the weather → block the day if unsafe (and say why).
  • Sort ponds by fill level: the fullest pond is served first, because it is closest to overflowing.
  • Pick eligible groves (not excluded by slope or distance, room left under the cap, under the daily dose), nearest first to cut tanker kilometres.
  • Assign tanker trips (4 trips per truck per day) until the pond is safe or the trucks are used up; update ponds, then go to the next day.
  • Same input → same output. Runs in milliseconds in the browser, so every slider moves the plan and the 3D instantly.

The Replay page runs the same engine over a whole season with and without Sonae, so we can show the spill that would have happened (for example 7,522 m³ spilled without Sonae, none with it, on the demo data).

4. The 3D digital twin and process view

  • Built with React Three Fiber: mills, ponds, groves, tankers, the wadi and the well are React components.
  • Not a video: pond levels, moving tankers, rain and blocked groves come straight from the engine's output for the selected day. Change a number in the plan and the 3D changes.
  • The Process page is a 9-step guided 3D sequence: margine settles in the pond → tanker → controlled spreading → potassium into the soil; grignon dries → becomes fuel → runs the well engine → pumps water back to the groves.
  • Performance: one shared canvas behind every page, lazy-loaded, simple geometry and instancing, pixel-ratio cap; it falls back to a gradient while loading and respects "reduce motion".

5. AI features (Claude Opus 5.5)

In the interface the AI is called "Sonae AI". Technically it is Anthropic's Claude Opus 5.5, called from our API with the official SDK. The API key stays on the server.

FeatureWhat it doesHow it is built
Lab readerA farmer or mill uploads a lab analysis (PDF, photo or text, in French, Arabic or English). Sonae extracts pH, potassium, polyphenols, salinity and so on, and gives a safe dose for that batch.The PDF or image goes to Claude as a document or image block; the answer is forced into a Zod schema (structured output). If the document is not a margine analysis, it says so. Text inside the document is treated as data, not instructions.
Ask SonaeFree questions in Tunisian Arabic, French or English: "can I spread at Agareb this week?"Tool use: the model calls our own functions (spreading_forecast, check_grove, demo_region_plan), which run the real engine on real Open-Meteo weather. It answers from tool results, not from memory.
Season planAfter sign-up, a mill or a farmer gets a full plan for 15 Nov to 28 Feb, phase by phase, with risks and a checklist, shown with an animation.The code computes the facts first (hectares needed, pond autonomy, trucks, K₂O need, recommended m³), then Claude writes the plan as structured JSON around those numbers. The plan is saved in the database (Neon Postgres).
Arabic UIThe whole interface in Arabic.The 944 interface strings and 85 sentence templates were translated once with Claude and stored as JSON, so nothing is translated at run time.
Safety and cost controls: structured outputs (schema-validated JSON), adaptive effort, a refusal fallback, input validation with Zod, per-route rate limits (for example 4 plans and 6 questions per minute), and a budget guard: every call's token cost is logged, and the API refuses AI calls past a hard cap (20 USD for the hackathon). The whole development and testing cost about 0.20 USD.

6. Blockchain: the ZitounLedger contract

Why a blockchain here? Margine spreading involves parties who don't trust each other: the mill (wants to empty its pond), the farmer, the regulator (ANPE / the agriculture ministry, CRDA) and grignon buyers. Today the paperwork is paper and can be faked after the fact. An append-only public ledger gives a record that nobody, including us, can edit afterwards.

FunctionWhat it does
registerMill / registerGroveOnly the regulator role can register a mill or an approved grove with its season cap (area × 50 m³).
declareMargineThe mill declares the volume it produced.
dispatchThe mill sends one load to a grove. The contract refuses it if it would exceed the grove's cap (CapExceeded error). It stores a hash of the lab report and reserves the volume.
confirmDeliveryThe farmer (or a GPS/flow-meter oracle) confirms within 2 days; the volume becomes "applied".
expireAn unconfirmed load expires: the fee goes back and the mill gets a red flag.
listGrignon / buyGrignon / confirmGrignon / refundGrignonGrignon market with escrow: the buyer's money is locked until delivery is confirmed, otherwise refunded.
issueCertificateZero-Spill clean-oil certificate: only issued if the mill's record is clean (everything delivered, nothing expired). Shops and exporters can check it.
pause / rolesOpenZeppelin AccessControl: REGULATOR, MILL, ORACLE, PAUSER, ADMIN. Emergency pause. ReentrancyGuard on every function that moves money.
On chain: grove ids and caps, load volumes, statuses, timestamps, lab-report hashes, escrow, certificates. Off chain: names, phone numbers, the PDFs, accounts. So personal data stays private, but anyone can check that the numbers weren't changed.
Deployed: ZitounLedger 0x094B7a274D9121513A5F04055Aa24aB7F8F16958 on Sepolia, source verified on Sourcify. Seeded with 6 groves and one mill; the live demo sends real transactions (dispatch, confirm, certificate).

7. Back end, data and security

  • Accounts: three roles (admin, mill owner, farmer). Passwords are hashed with scrypt (random salt, constant-time comparison). Sessions use a random token; only its SHA-256 hash is stored, and it expires after 7 days.
  • Authorization: every /me and /admin route checks the session and the role. The admin can suspend accounts.
  • Packs: mills pay Essentiel 390 TND / Pro 950 / Coopérative 2,400 per season, plus a per-m³ overage; farmers are free (Voisin), or 35 to 55 TND/ha for planning extras. The API computes the estimate.
  • Hardening: helmet security headers, CORS allow-list, global rate limit (120 requests/min) and stricter limits on login and AI routes, Zod validation (invalid input → 400), and secrets only in .env (never committed).
  • Database: Postgres tables for users, sessions, mills, farms, subscriptions, season plans and the AI spending ledger. The tables are created automatically on first start.

8. Mobile, offline and languages

  • PWA: installable from the browser; a service worker caches the app shell so it opens with no network.
  • Android: the same build wrapped with Capacitor (native status bar, splash screen, haptics).
  • Responsive: a top nav on desktop, a bottom dock on phones and tablets; tested from 375 px to 1440 px.
  • Arabic / English: one toggle switches every page, sets dir="rtl", the Arabic font, and the AI's answer language.
  • Farmers without smartphones: the engine already generates SMS texts for the farmer and the driver ("tomorrow 15 m³ to your grove"); plugging in an SMS gateway (for example Tunisie Telecom or Twilio) is the next step.

9. Testing and quality

  • 25 engine tests (Vitest): caps, rain blocks, slope and distance exclusions, fullest pond first, the season replay.
  • 21 contract tests (Hardhat): roles, the cap being refused on chain, delivery window, expiry, escrow refund, the certificate refused for a non-compliant mill, pause, reentrancy.

10. Deployment: how the live site runs

Vercel CDNThe built React app (static files) is served from Vercel's global edge network over HTTPS. Unknown paths fall back to the app, so deep links like /yui?cert=3 work.
Vercel FunctionThe whole Fastify API, bundled with esbuild into one file (api/index.mjs), answers every /api/* request. Up to 300 s per call, enough for the AI season plan (~30 s).
Neon PostgresManaged serverless Postgres, provisioned from the Vercel Marketplace; its connection string is injected as DATABASE_URL.

Why the database is not SQLite after deployment

Locally the API uses one SQLite file, which is perfect for development. A Vercel function, however, runs in short-lived containers: there is no permanent disk, several copies can run at once, and each starts empty. A SQLite file there would lose every account and plan. So in production the same code switches to Neon Postgres:

  • One small data layer (db.ts) with two drivers: if DATABASE_URL is set it talks to Postgres over HTTPS, otherwise it opens the local SQLite file. Queries are written once, in SQL that both understand.
  • The schema is created on the first request (CREATE TABLE IF NOT EXISTS), with Postgres types (identity ids, double precision).
  • The AI budget ledger moved from a JSON file into a database table, so the $20 cap holds across every function instance.
  • At launch, the local data (demo accounts, mill and farm profiles, the saved season plans) was copied into Neon with an insert-only script.

Secrets and settings

  • The Anthropic key, admin and demo passwords, API token and RPC URL live in Vercel's encrypted environment variables (sensitive ones marked "sensitive"), never in the code or in the browser bundle.
  • .vercelignore blocks every .env file from being uploaded. The blockchain private keys are not on Vercel at all: users sign with their own wallet.
  • The front end calls the API on the same domain (/api), so there is no cross-site traffic; CORS is still limited to the live domain.

Deploy flow

vercel deploy --prod → Vercel installs the monorepo, bundles the API, builds the web app (Vite + PWA) and publishes both in about a minute. Reads of the blockchain go straight from the browser to Sepolia, so the contract needed no change.

11. Likely jury questions, with short answers

Product and data

Where do your rules (50 m³/ha, 8 mm…) come from?
From Tunisian practice for controlled margine spreading on olive groves and the agronomy literature (Sfax region trials). They are parameters in one config object, not hard-coded, so a regulator can change them and the whole system follows.
Is the data real?
The weather is real and live (Open-Meteo, Sfax and any town). Mills and groves are a realistic demo dataset; a real mill types its own pond, production and groves in "My mill", and the plan uses them right away.
Why not just use machine learning to plan?
Safety rules must be exact and explainable. A deterministic engine gives the same answer every time, and a regulator can audit it. We use AI where it adds value: reading documents, natural-language questions, and writing the plan.
How accurate is the weather?
Open-Meteo combines national weather models; the planner is conservative: it also blocks the day before rain and wet-soil days, so a forecast error errs on the safe side.

AI

Which AI model, and why that one?
Anthropic's Claude Opus 5.5 through its official API. It reads PDFs and photos natively, handles Arabic and French, supports tool use and strict JSON output, which we need for lab reports.
What if the AI hallucinates?
It can't change the safety numbers: caps and doses come from the engine and the contract. Answers come from our tools running on real data, outputs are schema-validated, and a document that isn't a margine analysis is rejected.
Prompt injection in an uploaded PDF?
The system prompt tells the model to treat document text as data; the output must fit a fixed schema, so it has no way to run actions. The model has no write access to anything.
What does the AI cost at scale?
About 0.01 to 0.05 USD per lab reading or question, and a few cents per season plan. Even a Pro mill with hundreds of calls a season costs a few dinars; it's covered by the pack price. A hard budget cap stops runaway costs.
Is the farmer's data sent to the AI?
Only what the question needs (area, slope, place, the lab values). No passwords and no phone numbers. The key stays on our server.

Blockchain

Why blockchain and not a normal database?
Because the parties don't trust each other and the regulator needs proof. A database we own could be edited by us or by the mill; the ledger can't be rewritten, the cap rule runs in public code, and anyone can verify it without asking us.
Why Sepolia? What about production?
Sepolia is the free public Ethereum testnet. For production, the same contract deploys unchanged to a low-fee EVM network (for example Polygon PoS or an Ethereum layer 2), where a transaction costs a fraction of a cent.
Farmers don't have wallets or crypto.
They don't need to. Reading the ledger needs no wallet. Writes are done by the mill and the regulator; a farmer's confirmation can go through the oracle role (an SMS reply or the tanker's GPS and flow meter), with the platform paying the gas.
What stops a mill from lying about a delivery?
The farmer or oracle must confirm, not the mill. Unconfirmed loads expire and flag the mill, and a flagged mill can't get a Zero-Spill certificate. Lab reports are hashed on chain, so they can't be swapped later.
Is personal data on the blockchain?
No. Only ids, volumes, timestamps and document hashes. Names, phones and files stay in our database.
Is the contract secure?
It uses OpenZeppelin's audited AccessControl, Pausable and ReentrancyGuard, custom errors, a pull-payment withdraw pattern, and 21 tests. Before real money we would add an external audit and a multisig for the admin and pauser roles.
What is the Zero-Spill certificate exactly?
An on-chain record proving that a batch of oil came from a mill whose margine all reached approved groves, under the caps, with nothing expired. Exporters and shops can check it from a QR code, like an eco-label that can't be faked.

Engineering

Does it scale?
Yes, it's already built for it. The planner runs in milliseconds and even in the browser. The API is a stateless serverless function that Vercel scales automatically, the data is in managed Postgres (Neon), and the front end is static files on a global CDN.
You used SQLite. Isn't that a toy database?
Only on the developer's laptop. Deployed, the same code runs on Neon Postgres, because serverless functions have no lasting disk. The switch is one environment variable, DATABASE_URL.
Where is it hosted, and what does it cost?
Vercel (site and API) and Neon (database), both on free tiers for the demo. For a real launch, paid tiers run roughly 20 USD a month each, plus AI usage, which the mill packs cover.
How do you protect the keys?
They're in Vercel's encrypted environment variables, only the server reads them, and .env files are never uploaded or committed. Passwords are scrypt-hashed and sessions are stored as hashes.
What happens if the database is slow or down?
The planner, 3D, replay and blockchain pages keep working because they don't need the database; only accounts and saved plans wait. Neon keeps automatic backups and point-in-time restore.
Does it work offline, in the field?
Yes for opening the app and the last plan (PWA cache). Live weather, AI and blockchain need a connection; SMS covers farmers without data.
How is the 3D made, and does it run on cheap phones?
Three.js via React Three Fiber, low-poly models, one shared canvas, a capped pixel ratio, and lazy loading. Phones get the bottom dock and a lighter scene.
How long did it take, and what's next?
Built during the hackathon as a full monorepo. Next: a pilot with one Sfax mill and its farmers, an SMS gateway, tanker GPS and flow meters as the oracle, a regulator dashboard, and a production blockchain network. The web, API and database are already deployed and live.
Can it work outside Sfax?
Yes. Weather works for any coordinate (Sfax, Sousse, Mahdia, Kairouan…), and the rules are configurable per region. The same model fits other agri-waste flows.
If you don't know an answer: say what is built today and what is the next step. For example: "Today the confirmation is done by the farmer in the app. In production it's the tanker's flow meter acting as the oracle; the contract already has that role."
